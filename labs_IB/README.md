# Лабораторная работа №3

**«Использование функций криптографического интерфейса Windows для защиты информации»**

Автор: Kanteev Sergei, группа IDB-23-08

Вариант 10: потоковое симметричное шифрование, режим не используется,
без добавления к ключу случайного значения, хеширование MD5.

Программа из лабораторной работы №1 (Java 17, Swing + NetBeans GUI Builder, PostgreSQL через JDBC),
в которую добавлена защита учётных записей от несанкционированного доступа.

## Как устроена защита

| Требование задания | Реализация |
|---|---|
| Файл с учётными данными зашифрован | в БД лежит только таблица `users_encrypted` с одной записью `data BYTEA` — зашифрованный список учётных записей |
| Сеансовый ключ из парольной фразы (CryptoAPI) | Java Cryptography Architecture — аналог CryptoAPI: `MessageDigest("MD5")` = `CryptCreateHash` + `CryptHashData`, ключ RC4 128 бит из хеша = `CryptDeriveKey` без `CRYPT_CREATE_SALT`, `Cipher("ARCFOUR")` = `CryptEncrypt` / `CryptDecrypt` (класс `Crypto`) |
| Расшифрование во временный файл / файл в памяти | временная таблица PostgreSQL `users` (`CREATE TEMPORARY TABLE`): видна только соединению программы и удаляется самим сервером при отключении |
| Проверка парольной фразы | после расшифрования ищется учётная запись `ADMIN`; если её нет или данные не читаются — фраза неверная |
| Неверная фраза или отказ от ввода | сообщение и завершение программы, зашифрованные данные не меняются |
| Повторное шифрование при выходе, старое содержимое стирается | `UserStore.close()`: учётные записи шифруются заново и перезаписывают `users_encrypted` |
| Временный файл удаляется | `DROP TABLE pg_temp.users`, затем соединение закрывается |

Если программа завершится аварийно, изменения текущего сеанса теряются, но зашифрованные данные остаются целыми,
а временная таблица всё равно удаляется сервером.

## 1. База данных

```
psql -U postgres -c "CREATE DATABASE lab3;"
psql -U postgres -d lab3 -f sql/init.sql
```

Таблицу программа создаёт и сама. Параметры подключения — `src/main/resources/db.properties`
(база `lab3`, чтобы не пересекаться с открытой таблицей из ЛР1).

## 2. Сборка и запуск

```
mvn clean package
java -jar target/lab3.jar
```

Через Nix: `nix-shell develop.nix`, затем `pg-start` (поднимает PostgreSQL в `./.pgdata` и создаёт базу `lab3`)
и запуск jar. После перезагрузки `pg-start` нужно выполнить снова.

## 3. Первый запуск

1. Программа просит задать парольную фразу для шифрования базы и повторить её.
2. Создаётся база с учётной записью `ADMIN` с пустым паролем и сразу шифруется.
3. Вход `ADMIN` с пустым паролем → программа требует задать пароль (как в ЛР1).

При следующих запусках сначала появляется окно «Расшифрование базы данных».

## 3.1. Перенос пользователей из ЛР1

ЛР1 хранит учётные записи открыто в базе `lab1`. Чтобы перенести их, таблицу нужно скопировать в `lab3`:

```
pg_dump -d lab1 -t users | psql -d lab3
```

После ввода верной парольной фразы программа добавит пользователей из этой таблицы
(при первом запуске — всех, включая `ADMIN` с его паролем; позже — только с новыми именами),
сразу зашифрует данные и удалит открытую таблицу `users` из `lab3`. База `lab1` не меняется.
